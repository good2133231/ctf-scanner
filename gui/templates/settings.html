A10 SSRF 受控回连（默认关）

原理：任务内起一个本机 HTTP 回连监听，为每个候选参数生成一个唯一 token，把 http://<回调基址>/<token> 喂进去；收到携带该 token 的 访问，就说明目标服务端真的按我们给的地址发起了出网请求 —— 这是 SSRF 存在性的 直接证据，不依赖任何错误回显。

局限先看清楚：本机监听只在目标能回访扫描机时有效 —— 扫描机在 NAT 后 / 云主机无公网 IP / 目标出网被拦时，一条回连都收不到，这是环境限制。 刻意不做：不打内网地址（127.0.0.1:8080、169.254.169.254 那类 属于利用，越线），不提交页面表单（可能是写操作，表单只被用来取字段名，注入一律走 GET）， 不做延时型判定。监听端口用完即关。

CT 日志在线查询（crt.sh，免 key）

查 https://crt.sh/?q=<域>&output=json，产出 证书维度记录（签发者 / 有效期 / 序列号 / 涉及的域名 / CT 条目数），字段口径与 scanner/certs.py 对齐，可直接进任务详情的「SSL 证书」页签（来源标成 ct）；这些证书覆盖的域名同时进「拓展域名」（来源 osint:ctlog）。 它与另外两处不是一回事：passive.py 的 crt.sh 只取主机名做子域收集、 certs.py 是对目标做真实 TLS 握手取线上证书、FOFA 的 cert= 是拿证书去反查共用资产的其它域名。

crt.sh 是公共免费服务，返回 HTML 限流页 / 超时 / 502 都是常态： 所有失败都只记一行日志并继续跑下一个域名，不会让阶段挂掉。 name_value 里的通配符（*.x.example.com）会剥掉 *. 再入库并单独标记，不会把 * 写进资产库。

情报与线索（默认关：产出的是"线索"，不是漏洞结论）

本面板各项产出的都是「线索」（独立 leads 表）： 续24 起不再进 GUI 页签与人读报告（MD / HTML），只在 JSONL 导出里以 type=lead 保留，不写漏洞、不计入漏洞数、不自动导入 POC。 线索的语义是"值得人工看一眼"，人工确认后才是漏洞 —— 所以默认关闭，避免线索堆积把结果淹没。

匹配是白名单式的：只有 scanner/intel.py::MATCH_RULES 里显式写过的资产信号（如 weblogic / tomcat / iis / phpmyadmin…）才参与，且要求情报侧的产品与厂商 关键词同时对上，宁可漏报也不制造噪声。拉取走一次 HTTP（单向下行，不向第三方发送目标信息）， 结果缓存到 data/intel/，缓存内不再联网；拉取失败会退回过期缓存并告警。

它不发任何请求，只读站点/目录/漏洞/C 段四类数据，产出软 404 模板、 高价值入口无结论、同标题多主机、目录命中离群、同 C 段多 IP 等线索（规则见 scanner/heuristics.py，阈值都写在代码里、刻意保守）。

需先在本机 config/keys.yaml 填 github.token（GitHub 代码搜索接口要求认证； 未配置时一次请求都不发，日志里会写明原因，而不是报"没查到"）。 本功能只落元数据（仓库 / 文件路径 / 命中规则名）—— 不保存文件内容， 避免把可能出现的凭据明文写进本地库、日志与报告；要看内容请人工打开线索里的 URL。 请求一律 auth=False：GitHub 自己的 token 只作为 Authorization 头发出，任务级登录态（目标侧 Cookie / Token） 绝不会发给 GitHub。三项限额的理由：代码搜索限流约 10 次/分钟， 所以只查目标的注册域（子域名与主域命中高度重叠），不逐个查子域名。
