## 1. 项目是做什么的

CTFScanner：面向 **CTF / 授权渗透测试**的资产测绘与漏洞初筛框架。把手工渗透的前半段流水线产品化：

子域名收集 → 子域接管 → 端口服务 → 存活探测 → 站点截图 → 外部情报拓展 → JS 资产挖掘
→ 目录发现 → 漏洞初筛 → 情报订阅 / 启发式候选（**共 11 阶段**）。

两种入口：CLI（`cli/client.py`）与 Flask Web 控制台（`run_gui.py`，仿 ARL，9 栏侧边栏 + 任务详情 10 页签）。
数据落 SQLite（`data/scanner.db`），产物落 `logs/task_<id>_<ts>/`。

**不可越过的红线**：仅用于自有或书面授权目标；检测一律非破坏性（只探测，无爆破 / 无写操作 / 无 DoS 延时）。

## 2. 当前架构

```
入口层   cli/client.py · gui/app.py + templates/static
编排层   scanner/runner.py（StageContext / PipelineRunner / 协作式取消）
阶段层   scanner/stages/*（11 个，STAGE_ORDER 就是唯一真相）
检测层   pocs/engine.py（nuclei 兼容子集）· owasp/checks.py（12 项）· fingerprint.py · evasion.py
基础层   utils.py（HTTP 唯一出口）· config.py · log.py
存储层   scanner/db.py（SQLite，每次调用独立连接）
```

三条贯穿性设计（改代码时必须保住）：

1. **外部工具优先 + 内置兜底**（subfinder / puredns / httpx / dirmap / fscan / nmap，找不到就降级，不崩）；
2. **所有 HTTP 必须走 `utils.http_request`**（UA 随机化、超时、`verify_tls` 的唯一出口）；
3. **漏洞 ≠ 线索**：`intel`（CISA KEV 情报）与 `heuristic`（零请求差分聚合）只写 `leads` 表，
   不写 `vulns`、不计入漏洞数、不自动灌 POC。

分级门控四层：阶段级 `enabled` → `checks.skip_severities`（info/low **连请求都不发**）→
按 OWASP 分类 / 单项开关 → `min_severity`（默认 medium，结果级收敛）。

## 5. 已知问题

**文档已记录、本次复核确认仍然成立**（详见 `AGENTS.md §7`）：

- Linux 实机从未跑过（本机无 WSL/Docker），只有 `[5o]` 静态审计兜底；
- POC 置信度未校准（312 个里 305 个是低置信），所以情报/启发式只到「线索」层；
- SQLite 单写者 + 每任务一线程，无任务队列；GUI 无 CSRF/HTTPS，仅限本机；
- **改完 GUI 代码必须重启进程**（`debug=False` 不重载，旧进程占着 5000 会让人误判"代码没生效"）。

**本次新发现、此前文档没有的**：

1. **深扫会漏掉浅扫能命中的高价值路径**（已修）：实测浅扫命中 `.env` + `.git/config`，
   深扫只命中 `.git` —— 未知技术栈时 `dirs_big` 前 400 条全是"字母序的运气"。
2. **`_layer_paths` 的顺序参数是摆设**（已修）：原实现是独立 `if` 依次 `append`，
   `shallow` 永远排第一，导致「深扫超集」与「Java 站先吃 jsp」两条既有断言互相打架。
3. **隔离测试用 POSIX 路径会写到盘符根**：Git Bash 里 `export CTFSCANNER_DB="$PWD/x.db"`
   传的是 `/c/Users/...`，Windows 解析成 `C:\c\Users\...`，库真就建在 `C:\c\` 下，
   且 `rel_display()` 会打印 `\c\Users\...` 这种残缺路径。**已清理，但未决定是否加防御**。
4. **`.trae/` 未跟踪也未忽略**：另一个 AI 工具的目录（`documents/` 里放着续 9 的设计稿）。
   它其实是"并行会话的工作记录"，建议要么加进 `.gitignore`，要么明确约定不提交。
5. **真实库几乎没跑过真目标**：`data/scanner.db` 只有 2 条用户任务（#146 `test` / #147 `1111`），
   说明 11 阶段流水线在**真实目标**上的验证样本仍然很少，多数结论来自本地靶场与回环。
6. **设计稿里的「端到端手测」此前没人做**：续 9 的 `[5p]` 把 `run_task` 桩掉了，
   只验"走了哪一档"，不验"真跑出来什么" —— 这次补跑才暴露第 1 条缺陷。
