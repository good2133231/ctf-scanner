# 授权与法律声明

## 使用边界

CTFScanner 只允许用于以下场景：

1. 你本人拥有或有完整处置权的资产；
2. CTF 竞赛平台与官方靶场（HTB、VulnHub、DVWA、Pikachu 等）；
3. 已签署授权协议的渗透测试项目范围内、且在授权窗口期内。

对**任何未授权目标**使用本工具进行扫描/探测，在中国受《网络安全法》《刑法》第 285/286 条约束，在其他司法辖区同样可能构成刑事犯罪。

## 框架层面的克制

为降低误用与误伤风险，框架做了以下刻意限制：

- 所有内置 HTTP 检查仅使用 GET（及 POC 显式声明的 POST），无破坏性 payload；
- 不内置口令爆破、拒绝服务、漏洞利用功能；
- 所有自动化结论均为「潜在漏洞 / 初筛信号」，**不是漏洞结论**，报告强制提示人工确认；
- 内置动态免杀（`evasion`：UA/请求头伪装、payload 编码变形）**只用于提升探测隐蔽性、降低被 WAF 拦截的概率**，
  只改变 payload 的编码形态而不改变语义，**不改变上述非破坏性红线**（无爆破、无 DoS、无写操作）；
- 默认并发与目标上限收敛（`limits.*`），避免对目标造成压力；
- **外部情报拓展（`osint` 阶段）默认全关，且会向第三方披露目标信息**：C 段反查把目标 IP 提交给
  `api.webscan.cc`，favicon 反查把 favicon 的 mmh3 哈希提交给 FOFA。前者会让第三方知道你正在关注哪些
  IP，后者会消耗你的 FOFA 配额。**对敏感项目请保持关闭**；如需启用，请自行评估第三方服务的
  隐私政策与自身授权范围。
- **漏洞情报订阅（`intel` 阶段）默认关，方向与上面相反**：它是**单向下行**——从 CISA 拉公开的
  KEV 清单（`known_exploited_vulnerabilities.json`）到本地，**不向任何第三方发送目标信息**
  （匹配是纯本地字符串比对，只有拉取情报源这一个出站请求）。结果落本地缓存
  `data/intel/<source>.json`，可用 `intel.url` 换成自建镜像以完全离线；
  也可把 `intel.cache_hours` 调大减少出站频率，或设 0 关闭缓存（每次拉取）。
- **启发式候选（`heuristic` 阶段）默认关、且零出站请求**：它只读已采回的本机数据做差分/异常聚合。
- **GitHub 泄露检索（`github` 阶段）默认关，且是唯一"必须带自己的凭据"的第三方查询**：它拿目标的
  **注册域**去 GitHub 公开代码搜索（`api.github.com/search/code`）查命中 —— 也就是说，
  **开启它等于把目标域名交给 GitHub**（与 `intel` 反之，与 `osint` 类似的披露方向），
  **对敏感项目请保持关闭**。另有两条写死在代码里的边界：① 产出**只落仓库名 / 文件路径 / 命中规则名**
  这三类元数据，**绝不保存搜到的文件内容**（否则等于把可能命中凭据的明文写进本地库、日志与报告）；
  ② 调 GitHub 时 `auth=False` —— 任务级登录态（目标侧 Cookie / Token）**绝不外发**，
  发给 GitHub 的 `Authorization: Bearer <token>` 是使用者自己在 `config/keys.yaml` 配的 GitHub token，
  两者是不同来源的凭据。**没配 token 时一次请求都不发**（代码搜索接口要求认证）。
- **凭据（登录态）只有"带上它去扫"这一个用途**：任务级 Cookie/Token（GUI 文本框 / CLI `-H`、`--cookie`）
  由使用者在授权范围内自行取得，框架**不做**登录爆破、不自动提交表单、不解验证码。凭据**只发目标侧** ——
  `utils.http_request` 的 `auth=False` 是默认值，crt.sh / FOFA / CISA KEV / IP 反查这 4 个**第三方接口
  永不带凭据**（否则等于把目标会话外发给第三方）。日志、页面与报告一律**掩码**显示（`Cookie=SES***456`），
  凭据不进日志文件与交付物；解析非法行会**直接拒绝建任务并列出第几行**，不会静默丢弃。
  凭据本身仍写在 `tasks.options`（SQLite）里 —— 扫描期需要，故 `data/scanner.db` 视同敏感文件保管。
- 上述三个阶段产出的都是**「线索」而非漏洞结论**：框架在结构上做了隔离（独立 `leads` 表、
  独立计数，不进「潜在漏洞」表、不计入漏洞数、不自动导入 POC），
  因为它们来自外部情报、本地统计推断或第三方代码搜索，误报率天然高于实测型检查。
  **出口只有 JSONL 导出**（`type=lead` 行与 `counts.leads`）—— GUI 页签与人读报告（MD / HTML）
  自 2026-09-24（续24）起不再露出，避免误读成"已确认漏洞"。

## 使用者责任

- 自行确认目标授权、控制扫描强度与时段；
- 控制台/数据库包含资产与漏洞信息，注意本机访问安全（默认 127.0.0.1，请勿开放公网）；
- 本项目按现状提供，作者不承担因使用不当产生的任何责任。

## 控制台加固现状（续32）

控制台的定位是**单用户本机工具**（默认 `gui.host: 127.0.0.1`、单一口令、SQLite 无并发治理）。
除"默认只听回环"之外，2026-09-25（续32）起还有两道**技术守卫**（`gui/app.py` 的 `_local_guard`）：

1. **Host 白名单**：绑定回环地址时，`Host` 必须是 `127.0.0.1` / `localhost` / `::1` 之一，否则 403。
   挡的是 **DNS rebinding** —— 攻击者把自有域名解析到 `127.0.0.1`，浏览器就视其页面与本机控制台
   同源，于是能带 Cookie 打进来；叠加默认口令 `ctfscanner`（写在代码与文档里）即是**完整接管**
   （能用扫描器去打任意目标，并用上已配置的目标侧登录态）。
2. **写方法 Origin/Referer 校验**：`POST`/`PUT`/`PATCH`/`DELETE` 要求 `Origin`（缺失时退回 `Referer`）
   的**权威段**与本次 `Host` 一致，即 `主机[:端口]` 归一后相等（`_authority()`）——**端口参与比对**。
   比端口是必需的 —— **Cookie 不按端口隔离**，同机另一个 Web 服务（如 `127.0.0.1:9999`）向本控制台
   发请求仍算同站、Cookie 照样带上（`SameSite=Lax` 也挡不住，因为它是同站请求）。
   默认端口（http 80 / https 443）按协议归一后去掉，因为浏览器在默认端口下**不写端口**。
   `Origin: null`（`file://` 页面、沙箱 iframe）不放行；两个头都缺失时放行（curl/脚本必须能用）。
   > 这一条曾有缺陷（续32-fix）：首版两边都过 `_host_of()`，而它会**剥掉端口**，
   > 导致"同机异端口"整类请求被静默放行；该缺陷是在**真实服务器上实测**才暴露的
   > （test client 的默认 Host 不带端口，使对应的 smoke 断言假绿）。现已修复并补了端口断言。

会话 Cookie 显式设为 `HttpOnly` + `SameSite=Lax`（不依赖浏览器默认值）。
**刻意不做**逐表单 CSRF token：控制台的表单与 fetch 调用点有几十处，漏掉任何一处就是
"看起来有防护、实际有缺口"，而中间件层的 Origin 校验一次性覆盖所有写操作。

**仍未提供**：多用户与角色、访问审计、HTTPS。若你确实要让别人访问（团队/远程）：

- 把控制台**保持绑在回环地址**，由反向代理（Nginx/Caddy 等）对外提供入口，并**在反代层**做
  强口令或 mTLS + TLS 终止 + 访问日志；不要直接把 `gui.host` 改成 `0.0.0.0` 暴露给外网。
- 若你**确实**把 `gui.host` 绑到非回环地址，`serve()` 启动时会打印显式告警，且 Host 白名单会
  **自动放宽**（框架无法预知你用哪个地址访问）—— 换句话说，那一刻起上面第 1 道守卫不再生效，
  安全边界完全交给你的网络环境。
- 改掉默认口令（`config/settings.yaml` 的 `gui.token`）：注意它同时是 Flask 会话密钥的派生源
  （`app.secret_key = "ctfscanner::" + token`），口令公开等于会话可被伪造。
